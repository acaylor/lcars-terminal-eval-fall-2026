## Source inspection notes (file:line)

### Architecture & main loop
- `cmd/lcars/main.go:14-52` handles flags, the interval clamp to 200 ms–5 s, and the TTY check (`:45`).
- `app.go:82-172` `Run`: raw mode, `sync.Once` restore with defer, a key-reader goroutine, a signal channel (INT/TERM/HUP/WINCH), a 1 s sample ticker and a 400 ms animation ticker that redraws only when paused or in help. Sampling is synchronous on the loop (`app.go:195-206`).
- `view.go:116-137` dispatches by size and view: too small below 20x8, compact below 100x28, otherwise primary. Primary is built at `:148-374`, compact at `:376-411` (duplicate DrawText at `:407-410`), diag at `:413-461` and help at `:463-472`.
- Dead code: `app.go:26,42-45,158-163,298`, `Options.NoAlt`, `render/size_unix.go` (`readSize` unused, and its comment claims it "replaces the x/term GetSize dependency" while x/term is used), `theme.go:16-30` (`ANSI`/`ANSI256` unused), `shapes.go:190-255` (unused shapes), and `linux.go:18-20` (unused fields).

### OS collector interface & macOS backend
- The interface is `Sampler{Sample() Snapshot; Close()}` (`types.go:158-161`). Rate math is shared (`rates.go`, `collect.go`).
- Darwin (`darwin.go`), line by line:
  - hostname via `os.Hostname` works. Uptime via `kern.boottime` (`:51-62`) works: 6d 18h 37m = ref.
  - CPU (`:68-94`): `kern.cp_time` is a FreeBSD sysctl and not present on macOS, so it returns N/A (confirmed in the capture). There is no `host_statistics64` or `host_processor_info`. Per-core is never collected (`:67` comment).
  - Load (`:96-116`): `struct loadavg {fixpt_t[3]; long fscale}` puts fscale at offset 16 on LP64, but the code reads a uint32 at 12, which is padding (0), so it returns false. The capture shows `--`. This is an FFI layout bug.
  - Memory (`:125-143`): returns ok=false unconditionally. Because `Sample` assigns Mem only when ok (`:34-36`), total and swap are also discarded, so MEM and SWAP show N/A even though `vm.swapusage` was parsed correctly (offsets 0/8 are right).
  - Disk via `unix.Statfs` (`:145-153`) works: 282.9/460.4 GiB, total = df.
  - Net (`:159-202`): `FetchRIB(NET_RT_IFLIST)` with raw reads at msg+36/+40. With `if_msghdr` (16 B header) plus `if_data`, ibytes/obytes sit at +56/+60, so the code reads `ifi_ipackets`/`ifi_ierrors`. The name map is indexed by all-message index while `mi` counts only IFINFO messages, so the lo0 exclusion is misaligned. `msglen < 60 → break` can abort on short RTM_NEWADDR messages. The capture shows RX 724 B/s and TX 0 B/s on a host with en0 traffic.
  - Processes (`:209-233`) use `SysctlKinfoProcSlice("kern.proc.all")`, a real API, and the count of 917 matches ref 916. But `p_pctcpu` is not maintained on macOS (always 0), it is encoded as fake cumulative "ticks", and the shared code then takes deltas of an instantaneous value. `e_xrssize` is 0. Result: every process shows `0.0 / 0 B`, ordered by PID.
  - Swap display additionally requires `MemOK` (`view.go:570-576`), so it can never show on Darwin.

### Forbidden-subprocess check
- Zero hits for `exec.Command` or `os/exec` in any Go source (static-scan SUBPROCESS 0). Only the dev tools in `tools/*.py` spawn the binary.

### Rate math & robustness edge cases
- CPU (`rates.go:12-43`): per-field `cur<prev` gives not-ok, total delta 0 gives not-ok, and the result is clamped to 0–100. Idle = idle + iowait.
- Net (`rates.go:65-74`): dt from `time.Time` deltas (monotonic clock); requires `Elapsed>0`. The rate is computed from the sum across interfaces (`linux.go:200-229`), so a per-interface decrease is masked, a total decrease gives 0 B/s with NetOK=true, and a new interface adds its whole counter.
- Process CPU (`rates.go:85-111`): a new PID has base 0, PID reuse (ticks<base) gives 0, and the sort is deterministic. Vanished PIDs are skipped (`linux.go:100-101`, `:258-262`).
- `--once` takes two back-to-back samples (`app.go:183-184`), so dt is a few ms and CPU% is noisy (6.5 % observed vs ~0.5 %).
- Names: `Sanitize` maps C0/DEL/ESC to U+FFFD (`rates.go:181-194`). `clipStr` counts runes (`view.go:502-511`) and `RuneLen` assumes 1 column per rune (`cell.go:73`), so wide characters are not handled. Hostnames are trimmed at the first '.' but not width-clipped in the telemetry column.
- Permission errors: every read failure is silently skipped and degrades to N/A.

### unsafe / FFI / panic audit & bounded memory
- 10 `unsafe.Pointer` reads in `darwin.go`, with no bounds-justifying comments beyond the length checks. The loadavg, net and cp_time layouts are wrong (see above). Unaligned `*(*uint64)` loads from `[]byte` are tolerated on arm64. `size_unix.go:16-17` (TIOCGWINSZ ioctl) is sound but dead.
- Panic: Go runs deferred `restore()` while unwinding a main-goroutine panic. A panic in the `readKeys` goroutine would bypass it (low risk). There is no `recover`.
- Bounded memory: `pushRing` cap 120 (`view.go:54-62`, tested in `view_test.go:147`). Per-tick maps are rebuilt. The 60 s RSS run went 8468 → 8656 KiB.

### Test quality & determinism
- `metrics_test.go` (linux tag): fixture parsers for stat, meminfo, loadavg, uptime, netdev and procstat (including the tricky comm). `TestCPUBusyPct` covers reset, zero and short counters. `TestComputeRates` covers 2 s dt CPU/net, zero elapsed and first sample. `TestComputeProcessRates` covers top-N and dt=0. Format and sanitize are also tested.
- `render_test.go`: rgbTo256, diff (first full, unchanged small, changed cell, invalidate), big font, braille/ASCII trace, shapes/clip.
- `view_test.go`: 120x36 primary (no PID, clock and header present), diag, 80x24 compact (no big glyphs), tiny sizes no panic (1x1–40x10), help, ASCII purity at both tiers, key handling, ring bound.
- All are deterministic (fixed timestamps and fixtures). Gaps: no net counter reset or interface churn, no golden frames, no Darwin parser tests, and the tiny test only checks for no panic (it would not catch the 40x10 overlap).
