## Source inspection notes (file:line)

### Architecture & main loop
- `src/main.rs:11-38` dispatches between `--help`/`--measure`/`--dump`, a non-TTY error and the run path. `Term` is dropped at the end of the match arm, which restores the tty.
- `src/app.rs:9-57` is the loop: check quit and resize, sample when ≥1 s has passed, render to a `Buffer`, call `diff_rows`, write, then `poll_key(1000ms)`. `handle_key` is `app.rs:59-92`. It is concise.
- `src/render/mod.rs:53-57`: `render(sample, ui, w, h) -> Buffer` is pure and needs no terminal. `view.rs` holds three primary tiers (`:19-29`), diagnostics (`:263-338`) and help (`:379-409`).
- `src/term.rs` holds raw mode, the alt screen, signals, polling and key decoding.

### OS collector interface & macOS backend
- `metrics/mod.rs:106-141`: the `Collector` struct has a cfg-selected `inner` and duplicated cfg arms in `sample()`. This is a stable facade but not a trait. `Sample` (`:18-39`) is the OS-neutral contract.
- macOS (`metrics/macos.rs`):
  - CPU: `host_statistics64(HOST_CPU_LOAD_INFO)` into a `[u32;4]` with the correct count (`:196-216`).
  - Per-core: `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` with a bounds check `base+3 < info_count` and a correctly sized `vm_deallocate` (`:218-254`).
  - Memory: `hw.memsize` plus `host_statistics64(HOST_VM_INFO64)`, with available = free + inactive + speculative (`:101-119`, `:256-275`). Shows 10.3G against a vm_stat-derived reference of 10.2G.
  - Swap: `vm.swapusage` read as `xsw_usage` offsets 0 and 16 (`:277-296`), which is correct.
  - Network: `NET_RT_IFLIST2` parsed as `if_msghdr2` (via `read_unaligned`) plus the `sockaddr_dl` name at offsets 5 and 8, with 64-bit `ifi_ibytes/obytes` (`:298-366`). This is sound.
  - Uptime from `kern.boottime` (`:442-463`); load from `getloadavg` (`:465-475`); root disk from `statvfs` (`unix.rs:56-70`).
  - **Bug, `macos.rs:370-383`:** `proc_listallpids(NULL,0)` returns a pid **count** (libproc divides by `sizeof(int)`), but the code computes `count = bytes/4 + 64` and then `n = wrote/4`. The buffer is about ¼ size and the result is quartered again, so the process count is wrong (runtime N 74 vs 916) and top-5 scans a small subset.
  - **Likely bug, `macos.rs:153,158`:** `pti_total_user/system` are passed to `process_cpu_ns` as nanoseconds. On arm64 they are Mach absolute-time ticks, and there is no `mach_timebase_info` scaling. Every top-5 row on the Mac showed 0%.
  - No stubs. The `#![allow(deprecated)]` (`:4`) is explained.

### Forbidden-subprocess check
- `static-scan.txt` SUBPROCESS(0). Grep confirms there is no `Command::new`/`popen`/`system(`. Linux uses /proc (`linux.rs`). Time comes from `localtime_r` (`unix.rs:31-54`).

### Rate math & robustness edge cases
- Elapsed time comes from `Instant` deltas (`linux.rs:51-55`, `macos.rs:47-51`), and `elapsed > 0` gates every rate (`linux.rs:85,92,125,162`).
- `finite_elapsed` (`rate.rs:8-14`) and `counter_delta` (`:16-22`) treat a decrease as a reset, skipping the interval with `None`.
- `cpu_percent` returns `None` when d_total=0 (`:24-31`). Per-process ticks are divided by `clk_tck` and elapsed (`:33-40`).
- `iface_rates` matches interfaces by name, ignores new ones, drops vanished ones, and returns `None` if every interface reset (`:48-79`).
- PID churn: the map is keyed by (pid, starttime) and rebuilt each scan (`linux.rs:142,161,184`). A vanished `/proc/pid/stat` read means `continue` (`:156`). A `read_dir` failure means `None` (`:135-139`).
- Names: `parse_proc_pid_stat` uses `rposition(')')`, lossy UTF-8, filters control chars and takes 64 chars (`parse.rs:187-220`). Hostname is lossy and control-filtered (`unix.rs:4-15`). Width: `display_width` has a CJK and emoji wide table (`buffer.rs:171-190`), `fit` is width-aware with "…" (`:192-217`), and `Buffer::text` marks skip cells for wide glyphs (`:93-116`).
- Minor: `parse_proc_stat` uses `parts.next()?` on every line (`parse.rs:38`), so a blank line would void the whole CPU sample. That cannot happen with real /proc. Per-core matching is by index, so it is not hotplug-aware.

### unsafe / FFI / panic audit & bounded memory
- About 30 `unsafe` sites (`static-scan.txt`), all thin libc calls on zeroed or correctly sized out-params. None has a `// SAFETY:` comment.
- The signal handler only stores atomics (`term.rs:10-16`), which is async-signal-safe. `sigaction` has no SA_RESTART, so `poll` sees EINTR and exits promptly (`:146-156`, `:175-185`).
- `Cargo.toml:25` sets `panic = "abort"`, but `set_panic_hook` (`term.rs:138-144`) calls `restore()` before the default hook and abort, so the panic path is safe. `restore()` is idempotent through the `ENTERED` swap (`:122-136`).
- Bounded memory: `cpu_trace` is capped at 64 (`app.rs:29-32`). Prev maps and vectors are replaced on each sample. RSS stayed flat at 2792 KiB over 60 s.
- Completeness: no TODOs. The leftover scratch code and "Let me rebuild explicitly." comment in a test (`parse.rs:283-288`) are sloppy.

### Test quality & determinism
- `rate.rs:85-179` (6 tests): elapsed-based math, zero/negative/NaN dt, resets for cpu, proc and interfaces, long dt averaging, interface appear/vanish, all interfaces gone. These are deterministic and substantive.
- `parse.rs:226-316` (7 tests): /proc/stat guest columns and cores, meminfo with and without MemAvailable, missing mem → None, net/dev loopback and short lines, pid stat with nested parens and non-UTF-8, loadavg/uptime garbage, os-release.
- `font.rs:146-158` (1 test): glyph shape.
- `tests/layout.rs` (9 tests): 120x36 asymmetry and negative space, primary hides processes, diag shows them including the CJK name, 80x24/10x5/20x8/1x1 no-panic, ASCII-only and mono-no-truecolor, long hostname truncation, unavailable metrics are not zeros, focus/help/hold change the frame. `live_sample_survives_missing_fields` (`:153-175`) reads the live host, which is robust but not deterministic.
- Gaps: no assertion that 80x24 is a distinct simplified layout beyond no-leak and empty ratio, and no test of incremental (non-forced) `diff_rows`.

### Scope discipline
- No config, mouse, themes, plugins or process actions. `LCARS_TRUECOLOR` (`color.rs:30`) is an undocumented override, which is harmless. The process list appears only in `paint_diag`.
