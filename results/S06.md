## Source inspection notes (file:line)

### Architecture & main loop
- `src/lib.rs:1-5` exposes the modules buffer, metrics, model, render and terminal. `main.rs` holds only argument parsing (52-87), snapshot mode (89-116) and the event loop.
- `main.rs:146-210` polls input with a timeout capped at 100 ms up to the next 1 s sample deadline. Keys and resize trigger a redraw, and sampling happens on the deadline. Rendering is a pure `render::render(snapshot, history, view, w, h, options) -> Buffer` (render.rs:29-61), and `DiffRenderer` (buffer.rs:262-327) writes it. The loop is concise. `draw` takes 8 arguments under `#[allow(clippy::too_many_arguments)]` (main.rs:214).
- render.rs (1015 lines) mixes four layout tiers, widgets, a 5×7 digit font and a Braille plotter. It is cohesive but large.

### OS collector interface & macOS backend
- There is no platform-specific code: `grep cfg(` finds nothing. `Collector` wraps sysinfo `System`, `Disks` and `Networks` (metrics.rs:7-13). The only OS-flavoured detail is loopback name filtering (`lo`/`lo0`/`loopback*`, metrics.rs:130).
- On macOS, sysinfo 0.39 supplies CPU and per-core values (host_processor_info), memory and swap (host_statistics64/sysctl), disks (statfs/NSURL), networks (getifaddrs/if_data), and processes (libproc). `System::load_average()` and `System::uptime()` are used directly (metrics.rs:55-62, 93). `clippy-darwin-deny.log` is clean, and the macOS build and tests pass natively.
- There is no hand-written Darwin FFI, so there are no struct-size soundness issues.
- Local time uses `libc::localtime_r` (metrics.rs:150-177) instead of a `date` subprocess.

### Forbidden-subprocess check
- Static scan SUBPROCESS = 0. `Command::new` appears only in `scripts/*.py`, the dev harness, which uses `subprocess.Popen` to launch the binary under test. The application never shells out.

### Rate math & robustness edge cases
- `Collector::sample` measures `elapsed = now.saturating_duration_since(previous_sample)` (metrics.rs:31-33). `RateTracker::update` treats the first sample as a baseline, returns `None` on zero dt or on any counter decrease, and otherwise divides the delta by `as_secs_f64()` (model.rs:73-86).
- Interfaces are aggregated before the delta (metrics.rs:128-137). A vanished interface makes the sum decrease, so the code reacquires (safe). A newly appearing interface that already has large counters inflates the delta for one tick. There is no per-interface delta.
- CPU % comes from sysinfo's tick deltas. `finite_usage` clamps NaN or negative values (metrics.rs:142-148). History is clamped to 0–100 (model.rs:111).
- PID churn: `refresh_processes(ProcessesToUpdate::All, true)` removes dead PIDs (metrics.rs:38). Processes are refreshed only while the diagnostic view is active. As a result, the first refresh after a toggle compares process CPU time accumulated since startup against a 1 s global CPU delta. That inflates CPU% (931% observed in tab1-120x36.txt).
- Linux process count and top-5 include sysinfo "tasks" (threads): 1626–1634 shown vs 504/505 real. The code never filters on `thread_kind()`.
- Long or non-ASCII names: `clip` is width-aware and skips control characters (render.rs:811-826). `Buffer::text` reserves a continuation cell for wide glyphs (buffer.rs:189-212). The hostname is clipped to 28 or 20 columns. Process names are clipped to 20 or 15.
- Permission errors are absorbed inside sysinfo, and missing values become `Option::None` (memory total 0, root disk not found, non-finite load). `cpu` and `uptime` are hard-wired `Some` (metrics.rs:93-94), and `Collector::new` can never return `Err`.

### unsafe / FFI / panic audit & bounded memory
- There are 2 `unsafe` blocks (metrics.rs:158, 163). Both are minimal and correct (`MaybeUninit<tm>`, null-check before `assume_init`) and carry SAFETY comments.
- `panic = "unwind"` (Cargo.toml:21). `TerminalSession::drop` shows the cursor, leaves the alt screen and disables raw mode (terminal.rs:34-41), so a panic unwinds and restores. There is no panic hook, so a panic message would print into the alt screen before restoration (cosmetic).
- Signals: signal-hook flags for SIGINT, SIGTERM and SIGHUP (main.rs:120-123) are checked each ≤100 ms iteration, leading to a clean `Drop`.
- Memory is bounded: `History` is a VecDeque capped at 180 (model.rs:107-112), and the buffers are reallocated per frame at the screen size. The 60 s RSS drift was 36 KiB.
- Latent issue: `braille_trace` computes `current as u32 - 0x2800` (render.rs:982), which would underflow if the trace area held a non-Braille glyph. That area is never pre-filled, so it is not reachable in practice.

### Test quality & determinism
- `model.rs:173-254`: elapsed-time rates (500 ms giving 4000 B/s), reset, zero dt, a 1 h interval, history capped at 180, byte formatting.
- `buffer.rs:588-610`: wide-glyph clipping and continuation cells; 0..4×0..4 buffers that must not panic.
- `render.rs:1010-1014`: width-aware `clip`.
- `tests/rendering.rs`: required primary metrics with no process list (79-109); ≥20% negative space, rail counts and half-block clock (111-145); diagnostics plus five processes including a CJK name (147-182); 80x24 simplification (184-201); 264-combination size/view/ASCII sweep with an ASCII-only assertion (203-233); help and pause (235-253); diff renderer emits only the changed cell at `\x1b[2;4H` (255-277).
- All tests are fixture-driven and deterministic. Gap: nothing covers sampling or parsing of OS data, and `Collector` cannot be tested without a live OS.

### Scope discipline
- There is no config file, mouse capture (mouse_enable=0), extra theme, protocol or kill/renice. The CLI flags are `--ascii`, `--mono`, `--snapshot`, `--help` and `--version`. `--snapshot` is a documented non-TTY path, not bloat.
