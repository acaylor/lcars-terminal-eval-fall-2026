## Source inspection notes (file:line)

### Architecture & main loop
- Layering is documented at lib.rs:1-9. `App` holds state; `handle_key` is a pure transition (app.rs:76-98); `draw` builds a pure-data `Scene` (app.rs:110-124); `run` is a short sample→render-if-due→compute-wake→`event::poll(timeout)` loop (app.rs:138-213). No busy-wait: the timeout is the minimum of the next frame (250 ms), the next sample and the deadline (app.rs:182-189).
- Headless `--snapshot WxH` takes two samples 300 ms apart and renders to text (main.rs:128-138). Run errors call `restore()` before exiting (main.rs:149-153).
- Views: `ui::draw` dispatches on `View` and `Tier` (ui/mod.rs:138-148). Tiers are Tiny <60x16, Compact <100x30, Standard (ui/mod.rs:80-88).

### OS collector interface & macOS backend
- `Collector { static_info, sample(want_processes), warnings }` (metrics/mod.rs:120-127). `Snapshot` holds raw counters with every field optional (metrics/mod.rs:77-89). Platform selection is at metrics/mod.rs:129-138.
- macOS (macos.rs), line by line:
  - CPU total: `host_statistics64(HOST_CPU_LOAD_INFO)` with `HOST_CPU_LOAD_INFO_COUNT` (159-176); busy = user+sys+nice, idle = idle (151-157).
  - Per-core: `host_processor_info(PROCESSOR_CPU_LOAD_INFO)`, `chunks_exact(CPU_STATE_MAX)`, then `vm_deallocate` with `count*sizeof(integer_t)` (178-206). Sound.
  - Load: `getloadavg` (208-215).
  - Memory: `hw.memsize` + `HOST_VM_INFO64`; used = (active−purgeable)+wired+compressor × `vm.pagesize` (217-241). Checked against the macOS vm_stat reference: (630950−31626+103454+141906)×16384 = 12.9 GiB, displayed "13G USED / 24G TOTAL". Correct.
  - Swap: `vm.swapusage` into `libc::xsw_usage`; total 0 → None (243-266). Reference total 0 → "NO SWAP ──". Correct.
  - Uptime: `sysctl {CTL_KERN, KERN_BOOTTIME}` timeval (268-290). Displays 6D 18:33:12, reference "up 6 days, 18:33". Correct.
  - Network: `NET_RT_IFLIST2` two-pass sysctl, walked by `ifm_msglen` with `read_unaligned` of `if_msghdr`/`if_msghdr2` and bounds checks; up and non-loopback only; 64-bit `ifi_ibytes/ifi_obytes` (294-341). If the buffer grows between the two calls you get ENOMEM, which becomes `None` plus a warning for that one sample. That is graceful.
  - Processes: `proc_listpids(PROC_ALL_PIDS)` with +64 headroom (343-363), `proc_pidinfo(PROC_PIDTASKINFO)` size-checked (365-381), `proc_name` into a 256-byte buffer (382-388). **Bug:** `Duration::from_nanos(pti_total_user + pti_total_system)` (392). On Apple Silicon those fields are mach_absolute_time ticks (timebase 125/3), so per-process CPU% comes out about 41.7x low. Confirmed in macos/diagnostic-120x36.txt: mediaanalysisd 2.9% vs `top` 115.2%, svc39 1.0% vs 34.9%. Ranking survives because the scale is uniform.
  - Disk: `statvfs("/")`, used = blocks−bfree (399-415). On APFS this gives container-wide usage, displayed 283G used / 460G total. `df /` reports only the sealed system volume (12.8G). This is defensible statvfs semantics and is not fabricated.
  - Identity: `kern.osproductversion`, `hw.ncpu`, `uname`, `gethostname` (38-57).
- Minor: `mach_host_self()` is called up to 3 times per sample without `mach_port_deallocate` (23-25), so the port's user-reference count grows.

### Forbidden-subprocess check
- No `Command::new`, `popen`, `system(` or `exec` anywhere (static-scan SUBPROCESS (0), confirmed with grep). Local time uses `libc::time` + `localtime_r` (app.rs:218-241). Hostname uses `gethostname` (metrics/mod.rs:141-149).

### Rate math & robustness edge cases
- `RateTracker::update`: measured `saturating_duration_since`; `elapsed<=0` keeps the old baseline; a 64-bit decrease returns None (reset); 32-bit wrap is unwrapped (rates.rs:33-54).
- `cpu_fraction` uses `checked_sub` on totals and busy; total 0 → None (rates.rs:58-65).
- Per-interface trackers are keyed by name and `retain`ed on each sample, so new or vanished interfaces cannot spike the total (sampler.rs:128-162).
- Per-process: dt from snapshot instants, `dt<=0` → None, `checked_sub` on CPU time handles PID reuse, `proc_prev` is rebuilt every scan so dead PIDs drop out (sampler.rs:168-198).
- Linux `/proc/<pid>/stat` is parsed from the last `)` (linux.rs:210-226). Unreadable or vanished entries are skipped (linux.rs:230-252). Each /proc file read records its own warning (linux.rs:39-53).
- Width: `char_width` table (CJK, Hangul, fullwidth, emoji) at buffer.rs:168-196. `fit` is width-aware with an ellipsis (buffer.rs:203-223). Wide-char tail handling is in `set`/`put_str` (buffer.rs:90-130). In ASCII mode, non-ASCII data becomes `?` (glyphs.rs:108-114). Top-bar host labels pass through `fit` (frame.rs:105-107).
- Nits: linux.rs:118-124 adds guest/guest_nice into busy even though the comment at :104 says the kernel already folds them into user (double count, VM hosts only). Collector warnings are never cleared after a metric recovers. diag.rs:291 uses `{:>6}` for PIDs, so 7-digit PIDs shift the name/CPU/RSS columns by one cell (visible in diagnostic-120x36.txt).

### unsafe / FFI / panic audit & bounded memory
- unsafe sites: `localtime_r`/`time` (app.rs:223-225); `sysconf`, `statvfs` (linux.rs:20-21, 264-265); `gethostname`/`uname` (metrics/mod.rs:143,152-153); `libc::signal` ×3 (session.rs:80-93); and the macOS calls above. All use libc-crate struct definitions, zeroed out-params, length checks, and `read_unaligned` for routing messages. The `gethostname` result is handled whether or not it is NUL-terminated (metrics/mod.rs:147). Not every block carries a SAFETY comment, but the non-obvious ones (vm_deallocate, 32-bit sysctl keys, IFLIST2 vs getifaddrs) are explained.
- Panic: Cargo.toml `panic = "unwind"` with a comment explaining why. The panic hook calls `restore()` and then chains to the previous hook (session.rs:94-98). `Drop for Session` (session.rs:55-59). `restore` is idempotent through `ACTIVE.swap` (session.rs:62-70). The signal handler is async-signal-safe because it only stores an atomic (session.rs:71-75). The loop checks the flag (app.rs:150).
- Bounded: `History` VecDeque capped at 240 (rates.rs:82-87, sampler.rs:8). Interface map is retained per sample. `proc_prev` is replaced each scan. Warnings use a BTreeMap keyed by static strings. perf long-run RSS: 2992→3088 KiB over 60 s.

### Test quality & determinism
- 63 tests, all with explicit `Instant` offsets and no sleeps. Two touch the live system (linux.rs:354 statvfs, app.rs:316 clock sanity).
- Sampling and parsing: proc_stat, loadavg/uptime, meminfo with and without MemAvailable, net_dev loopback skip, hostile pid name `my (weird) proc ñ日本` (linux.rs:284-352).
- Rate math: measured 1.5 s interval, zero dt keeps the baseline, 1 h gap, 64-bit reset → None then recovery, 32-bit wrap, CPU-fraction reset (rates.rs:116-172). Sampler: two-sample CPU, interface appear/vanish, missing metrics → None, process ranking with a vanished PID and a CJK name, top-5 cap (sampler.rs:218-340).
- Layout: tier thresholds (ui/mod.rs:188-195), segment and rail-block distribution, frame at 0x0..200x60 on both sides (frame.rs:309-391), a full size sweep for both views with and without help, including a long hostname (render.rs:271-291), and an 80x24 simplification check (render.rs:242-257).
- Terminal-independent rendering: a one-cell diff writes one cell; full frame; mono emits no `38;`/`48;`; wide chars (render.rs unit tests at term/render.rs:101-146); the clock tick changes fewer than 60 cells and under 2000 bytes (tests/render.rs:334-358); ASCII-only output (render.rs:259-269); negative space ≥20%; asymmetry.
- Gap: no fixture tests for the macOS collector. It is FFI-only and cannot be fixture-tested as written, and the units bug went uncaught.

### Scope discipline
- Primary view has no process list (render.rs:160-162; confirmed in primary-120x36.txt). No config files, mouse (`mouse_enable: 0`), themes, plugins or process actions. The CLI flags are modest and documented.
